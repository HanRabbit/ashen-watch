# 第二步：双鬼与生存机制

本轮检查日期：2026-11-22。范围是 PRD 第 8 节第 2 步，不包含正式美术交付与首玩测试。

## 本轮修改

- 修复纯鼠标右键的长短按边界：即使长按期间没有调用渲染帧的 poll，释放时也按实际按住时长判断，不会误发交互。覆盖阈值、正常长按、短按和失焦。
- 浏览器机器人从只读探针读取游戏的实际逼退半径，不再维护过期的距离常量。对已进入 recoil 的鬼继续保持照明，直到它放弃追踪或脱离持续照明距离，避免反复举放、重复扣启动油量。
- 新增四种修复方案的浏览器验收入口，以及纯鼠标回归和晨曦补取钟舌入口。输入均经键鼠事件，探针不修改游戏状态。
- 浏览器报告记录受击前后生命、灯油、是否举灯及附近鬼的状态，保留最近 40 次采样，便于后续复现失败原因。
- 修复机器人对调查状态的误判：声音调查不等于已经追击，避免守夜瞄准逻辑找不到对应目标。此问题由本轮栅门＋门闩浏览器用例发现，已增加回归测试。
- 敌人伤害、速度、资源数量和关卡规则没有因测试而放宽。

## 当前玩法参数（与早期 PRD 初值有差异）

以 src/config.ts 为准：白天 6 分钟、黄昏 90 秒、夜间 6 分钟；提灯初始 60 秒，每份油补 100 秒，上限 300 秒；举灯每秒耗 3 秒油，举起时另耗 3 秒。固定壁灯与两处火盆每份油燃烧 180 秒。炉火入夜 240 秒，每份木料延长 160 秒，室外寒冷阈值 160 秒。灰影伤害 25、黑影伤害 20；持续举灯约 3 秒后目标退走，暂时不再追踪。

本轮不重调这些数值。功能可通关与数值是否适合首次游玩的真人，是不同的验收项。

## 如何重跑

终端一：npm run build，再 npm run preview。
终端二：npm test，再 npm run verify:step2。

单项：node tools/browser-verify.mjs chrome --headless step2-none
Edge：node tools/browser-verify.mjs msedge --headless step2-late

step2-mouse、step2-none、step2-lamp-bolt、step2-gate-bolt、step2-lamp-gate 默认使用发布预设、正常模拟速度，允许正常的床铺/壁炉快进。step2-late 使用开发预设整体 2 倍速（dayClockScale=1），不跳过整夜，验证晨曦仍可补取钟舌；不是正常速度体验测试。AW_STEP2_FAST=1 是开发加速复查选项，不用于发布预设的验收结论。

原始浏览器记录及截图：docs/verification/browser-step2-*。

## 结果与边界

最终结果见下表。2026-11-20 的旧性能记录仍见 VERIFICATION.md。此次并行运行 Chrome/Edge 验收，不用这些报告里的帧率判断性能是否达标。

此前纯鼠标机器人失败，本轮的初始对照和修复后运行均未复现。代码检查确认了输入边界缺陷和机器人持续照明策略缺陷，但不能断言它们就是旧失败的唯一原因；报告现已保留受击上下文。

正式角色、动作、材质、采样音效属于第三步，5 位初见玩家测试属于第四步，均未在这里宣称完成。
