# 电影化视觉重建 · 实施与验收

## 不变的方向

以 [美术圣经](ART-BIBLE.md) 和 `concept/01–05` 为准：雨后深秋的哥特要塞，低饱和冷灰石、深色旧橡木、锻铁、冷雾与局部的琥珀火光。以石块切面、木构接合、衣料重量与真实透视建立可信度，不靠大面积高光、深暗角、持续镜头晃动或全场压黑。玩法、中文 HUD/无障碍提示、键鼠与纯鼠标操作沿用原契约。现有 `docs/COMPOSITION.md` 是场景组成参考，不以让单个验收机位匹配概念图为目标重新移动楼梯或门洞。

## 首轮切片

1. **角色**：真实位移驱动的走、跑、急停、转身；用开阔庭院、撞墙、楼梯检验重心、脚掌、持灯和衣料。
2. **近景资产**：庭院井及相邻交互轮廓；统一倒角、材质尺度、木铁接合和雨水趋向，保留碰撞与交互关系。
3. **灯光 / 大气**：昼夜与室内外分区取证，分清冷环境、实际照明的火光以及深处大气；保留低档可用。
4. **镜头 / 集成**：同路径复跑门房、地窖、礼拜堂和 2F，查看走动中途画面，而不是只检查十个停靠点；不以增加近景模糊换取所谓电影感。

敌人全套动作、全场模型与贴图替换、UI 全版式翻新、跨硬件性能矩阵是后续分项，不包含在首轮完成声明中。

## 验收与复跑

- 对比当前切片与 `8aa8aeb`：同画质、视口、初始日夜和相似路线。局部截图用来检查网格和材质；移动录像用来发现穿门、窄梯口镜头闪切、视差崩坏、步态滑动以及雾与灯光跳变。
- 全路线路径必须只通过真实键鼠，不可瞬移或锁定机位；动画/照明专项可设置**初始**位置或昼夜，需注明覆盖边界，不当成关卡通关。
- 先以 720p 高画质复跑基线，再按空闲 GPU 时段做 1080p 画质档对比；记录分辨率、画质、GPU、控制台、帧时间和场景，不把并行容器下的 FPS 当成跑分。
- 优先保证门洞和楼梯净空、交互、低档和原机制；以 `npm run build`、`npm test` 和实机报告共同验收。若不能验证则明确保留，不以文字宣称艺术终验。

```sh
npm run build && npm run preview -- --host 127.0.0.1 --port 4180 --strictPort
# 另一终端：
AW_URL=http://127.0.0.1:4180/ AW_ANGLE=metal AW_W=1280 AW_H=720 \
  AW_ROUTE_QUALITY=high AW_VIDEO=1 AW_OUT=/tmp/aw-cinematic-v1/route \
  node tools/browser-verify.mjs chromium --headless route
```

其余昼夜与动作命令、macOS Chromium 启动参数见 [之前的集成检查点](INTEGRATION-CHECKPOINT.md)。这些性能数据不代表其他设备或 GPU。
