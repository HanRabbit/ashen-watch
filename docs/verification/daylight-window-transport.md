# 白天窗边的空气与受光面

**环境：** Apple M3 Max，Chromium 的 ANGLE Metal / WebGL2，1280×720，默认 `cinematic`。场景、材质加载和跟随镜头均使用游戏本身；拒绝软件渲染。图像未经提亮。[四张实机图](daylight-window-views.jpg)；[门房行走片段](daylight-window-walk.mp4)。

**光从哪里来。** 门房两端铅条窗及礼拜堂西侧高窗使用各自的玻璃孔径与朝向。一个分量计算窗洞可见的漫射天光，另一个分量取来自当前方向光的、有真实阴影约束的散射。积分在不透明场景深度处截断。厚墙的内外窗洞、门房较窄的玻璃座，以及礼拜堂的隔墙和夹层会截掉不通的光路。射线不经过这些区域时跳过窗散射；高档 18 个深度区间、三分之一宽高；电影档 32 个区间、半宽高；复用原有深度与主光阴影，不再渲染一遍场景。低档直出不增加这道体积 pass。

**为什么不能只调曝光。** 后窗下暗石在显卡原始 HDR 中约为 0.0013，调色后却近乎纯黑。保留既有 ACES 中高调，只给暗部加一个以零为起点、单调且有上限的响应；没有把常量加到场景里。窗台与石材接收通过开口的天光及一次近似反弹；地下室深处没有这项通量。炉火、火盆和提灯的有限距离遮挡是独立的世界空间查询，不由相机所在房间决定。

## 实机对照

关闭门、炉火、提灯和火盆，真实指针锁定，WASD 走近、穿过窗前。从两个角度在**同一游戏更新**内各重绘关／开／再关，比较屏幕上投影的窗边空气范围，排除移动、昼夜和颗粒噪声。两个采样机位相距 2.14 m、视向相差 6.60°。礼拜堂与地下室另设初始站位，不冒充从门房一路步行到达。

| 站位 | 窗散射开关导致的变化（电影档） |
| --- | --- |
| 门房接近窗边 | 31,012 / 31,416 个 ROI 像素变亮，平均显示相对线性亮度增加 0.00095 |
| 门房斜向经过 | 68,362 / 71,264 个变亮，平均增加 0.00073 |
| 礼拜堂西侧高窗 | 11,213 / 11,224 个变亮，平均增加 0.00498 |
| 入夜的门房；白天密闭 B1 | 两个对照的**整幅图**都没有超过关／关噪声的像素变化 |

高档也在同一条路线用 Metal 实测：两个门房站位都有正信号，夜窗和 B1 负对照无变化。

另用七张游戏状态图检验**表面**（不是用雾代替照明）：无火时后窗下石面白天 `0.00347`、入夜 `0.00027`；白天深侧墙 `0.00213`。B1 东侧石墙日间熄灯 `0`，提灯点亮 `0.00814`。入夜炉侧砌体从约 `0.000001` 回到 `0.15442`。这些是从最终显示图像解码的相对亮度，不是勒克斯。

湿地反射另测：东池／北池分别有 7／292 个带有当前帧辐射的原始 GPU 命中；将反射入射图置黑后，命中仍可存在，但无正反射能量或额外屏幕增亮。使用的是结构遮挡射线与屏幕空间反射，而不是全场景三角网格路径追踪。整帧探针受启动、编译、自动化录制影响；本轮不据此宣称帧率提升。

**焦散单列，不计入通过项。** 在门房阴天的受光地面，玻璃折射开／关／再关的 828 个最终显示像素没有可测差异；去掉方向光的负对照也是零。已核对接收材质确实参与绘制，并修复了 VSM 模糊会覆写几何深度的问题。这个结论不影响以上体积散射和湿地反射的独立对照。没有为制造可见焦斑而增加光源或绕过墙体。
