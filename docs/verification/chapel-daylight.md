# 教堂日光：从门厅走到祭台

2026-11-24，Apple M3 Max / Chromium WebGL2 / ANGLE Metal，1280×720。[五个游戏视角的前后对照](chapel-daylight-views.jpg) · [连续实走录像](chapel-daylight-walk.mp4) · [读数、相机与光源状态](chapel-daylight-readings.json)。对照图和录像没有提亮。旧版为 `ac1efbb`。

## 改在哪里

- **玻璃不是石板。** Three r187 的 [WebGLShadowMap](https://github.com/mrdoob/three.js/blob/r187/src/renderers/webgl/WebGLShadowMap.js) 在 VSM 模式还会绘制接收阴影的物体。只对透明玻璃批次关闭两个阴影标志；单独的铅条、石窗棂、鞍杆和围墙保留真实阴影。玻璃表面的透光颜色取自当帧天空，不再按昼夜预设自发光。
- **石面与空气分别受光。** 从 13 个有玻璃的开口离线计算天空可见度，以及天空照到部分石面后的一次漫反射。地表用带方向的三维纹理，在材质受光阶段取样。地面、门厅隔墙和上廊用较密采样，屋顶以内的高处用较疏采样。窗洞面积、朝向及隔墙会影响结果；教堂以外和夜间不加这部分光。不更改全局曝光、环境灯或碰撞。
- **光束有起止。** 漫射天光查另一张 71 KiB 的单通道场；直射则把真实主光投回窗洞，同时检查内外两道窗缘、室内遮挡和实时阴影。只在视线实际穿过的光束长度内积分，并在前景深度停止。这样既保留窗棂之间的暗缝，也不会产生早期候选版本中随相机移动的等距黑边。新增计算复用已有体积 pass、深度和阴影图。高档及电影档支持，低档没有增加体积 pass。

## 实走与结果

人物只在路线开始时设置于关门后的教堂入口。提灯、火盆、炉火和壁灯熄灭；通过真实鼠标锁定和走路输入，绕过隔墙进入侧廊，走到中殿和祭台。下表是五个玩法视角，不是开发者固定相机。每站待相机转动结束，在同一游戏更新内渲染散射 **关 / 开 / 再关**。前后版本是分别重走，人物位置、颗粒等可能略有不同，不用两次重走间的逐像素差作为验收。

| 电影档视角 | 关散射的亮度：旧 → 新 | 加入散射后有明显增亮的画面选区：旧 → 新 |
| --- | ---: | ---: |
| 门厅看开口 | 0.00085 → 0.00802 | 0% → 5.9% |
| 侧廊看长椅 | 0.00338 → 0.01052 | 0% → 37.9% |
| 中殿看祭台 | 0.00092 → 0.00780 | 0% → 13.4% |
| 中殿回望西窗 | 0.02287 → 0.03062 | 0.14% → 32.9% |
| 祭台回望上廊 | 0.00487 → 0.00997 | 0.07% → 11.5% |

亮度为最终 sRGB 图像解码后的显示相对线性 Y，不是勒克斯。统计固定屏幕范围 `x=.27… .88, y=.14… .76`，避开大部分暗角；门厅与正看祭台的范围不含明亮窗玻璃。明显增亮指同一站位开/关差值超过关/关噪声 + 0.006 Y，且至少一个 RGB 通道增幅（绝对码值差）达到 5/255。明窗入镜的中殿回望视角不用于衡量砌体提亮倍数。

**负对照：**两档在夜间祭台和白天封闭 B1 的整幅画面，开/关散射都没有超出重复帧噪声的像素。另查 B1 的绝对值：电影档全帧约 0.0000038，避免把“开关一样亮”的漏光误判为通过。仅把体积着色器实际收到的天空和方向光同时置零，没有像素达到明显增亮阈值；仍允许尘气吸收背景光。门房原有的闭门走窗路线也另行通过。

**开销：**地表和空气场合计 934,461 字节原始数据，运行时不烘焙。地表场每个受影响的片元用两次三线性读取。空气沿用半宽高 32 步（电影）/ 三分之一宽高 18 步（高）的天气积分；按光束长度自适应的直射积分另外耗费窗内采样，没有为此重绘场景。每站预热后记录 32 个普通动画帧，电影档五站的中位帧间隔均为 16.7 ms，P95 为 16.7–16.8 ms。这是单机短采样，不是 GPU pass 计时、首次冷编译时间或其他设备的帧率保证。
